# AlphaWRT 0.5.0

- **Channel:** Release
- **Target:** Skyworth GN630V AX3000 (Airoha EN7523 / AN7529CT)
- **Build:** OpenWrt r37113+197-e4974473db, built by `build.sh` from `config/gn630v.config` and `config/feeds.conf` at this tag, on a local machine (clean build)
- **Acceptance:** see "Hardware acceptance"

> **Do not flash the 2.5G GN630V.** This build supports only the AX3000 GN630V. The 2.5G variant is untested and may be incompatible. Check the full model marking on the label.

0.5.0 fixes the idle CPU load from the Wi-Fi interrupt ([#6](https://github.com/idiazraz/gn630v-alphawrt/issues/6)) and Unifi (TM) lines that registered but never got internet, and adds the phone (TEL) port, a Speed test page, a light/dark switch, PPPoE login editing, the fibre password on the Fibre page and internet over the box's Wi-Fi in bridge mode. It includes everything from the 0.4.2-test and 0.4.3-test tester builds.

## Downloads
- `*-tclinux-factory.bin`: first install, from the stock firmware web UI. Keep `tclinux` in the file name.
- `*-sysupgrade.bin`: upgrade a running AlphaWRT. Never sysupgrade the stock firmware.
- `*-initramfs-kernel.bin`: RAM boot over U-Boot TFTP, for recovery and backups ([INSTALL.md](https://github.com/idiazraz/gn630v-alphawrt/blob/v0.5.0/docs/INSTALL.md)).
- `SHA256SUMS`: check the file before flashing.
- `*.manifest`: the package list of this build.

The stock firmware stays in the other flash bank, so you can always switch back. Read the [recovery guide](https://github.com/idiazraz/gn630v-alphawrt/blob/v0.5.0/docs/RECOVERY.md) before flashing.

## What's new since 0.4.1
### Added
- **Phone on the TEL port.** Plug in a normal home phone and set your provider's SIP line on the new Phone page: lift the handset for a dial tone, dial out, and incoming calls ring the phone. Calls use G.711 over plain SIP (UDP).
- **Internet over this box's Wi-Fi in bridge mode.** If you keep the box's Wi-Fi on in Quick Setup and give your router's 192.168.100.x address, Wi-Fi devices (and LAN 2-4) reach the internet through your router. Your router needs that second address on its Internet port and must forward the box's traffic, as for Pi-hole. Rerunning Quick Setup in bridge mode no longer switches the box's Wi-Fi off.
- **"Skyworth GN630V (TM-supplied)" in Quick Setup's fibre box list** for Unifi, with the values TM expects. You still enter the serial and PLOAM password from your TM unit.
- **Speed test** page: download, upload, ping and jitter, measured by the box itself against the nearest Speedtest.net servers, or one you pick. Wi-Fi and your own device don’t slow the result.
- **Light and dark mode switch** in the Simple UI (sidebar, or the top bar on a phone) and in Advanced (LuCI): Auto follows your device, or pick Light or Dark. Both share the choice.
- **Change the internet login** (PPPoE username and password) from the Network page, without running Quick Setup again.
- **Fibre page shows the serial number and PLOAM password** the box gives your provider. The password stays hidden until you tap the eye.

### Fixed
- **Fibre could stay down for hours after a short drop:** after a 1-second loss of signal, some OLTs keep rejecting the box each time it registers again. After two quick rejections in a row, the box now keeps its laser off for a minute before trying again, as a restart does.
- **Wi-Fi page showed 2.4 GHz at 40 MHz while it ran at 20 MHz.** With other Wi-Fi networks nearby, 2.4 GHz steps down to 20 MHz so it doesn't step on them. The page now says so under the Width setting.
- **One CPU core busy even with nothing happening:** the Wi-Fi interrupt fired about 115,000 times a second at idle, keeping `ksoftirqd/0` busy ([#6](https://github.com/idiazraz/gn630v-alphawrt/issues/6)). It now only fires for real Wi-Fi work. Speeds were never affected, only spare CPU.
- **2.4 GHz Wi-Fi could stay off after a restart:** on Auto channel, the box could pick channel 14, which Wi-Fi 4/5/6/7 can't use, and 2.4 GHz didn't start. Auto now picks from channels 1-13.
- **Unifi (TM) fibre: no internet on a TM-supplied GN630V.** The stock-identity import now sends what the stock firmware really sends TM: vendor CWTC, model GN630V, hardware version CW1.0 and OMCC 150 (not the SKYW/PT632/RP0201/A0 values in its settings), with the box's own serial and the stock firmware's image versions. With those, TM's equipment sets up the line. Confirmed on a live Unifi line.
- **Unifi (TM) fibre: no internet, the line registers but never gets service.** The box now tells the provider's equipment about every kind of setting the stock firmware supports, so TM's Nokia equipment no longer stops before setting up the internet connection.

### Known issues
- **Phone line:** tested on our unit with calls between the box and a test line, not yet with a provider's line (Unifi's voice VLAN included). There is no echo canceller, so on some phones you may hear a faint echo of your own voice. SIP over TLS and encrypted calls (SRTP) aren't supported.
- Turning "Stop devices skipping Pi-hole" on or off drops name lookups for about 15 seconds while Pi-hole restarts.

## Reproducibility
**Not checked for this tag.** What is known: `build.sh` pins the tree, the patches, the feeds and the commit dates, so the revision and `SOURCE_DATE_EPOCH` are the same on every machine. The images contain no build path, user or host name, and every timestamp in them comes from `SOURCE_DATE_EPOCH`. Two builds still differ in `/etc/apk/keys/public-key.pem`: OpenWrt makes a new package-signing key per build tree, so the rootfs and image checksums differ unless both builds use the same key.

Builds from different machines also differ in the key, so a local build and a CI build of the same tag don't have the same checksums.

## Known issues and test limits
- **SQM and hardware offload:** traffic the hardware packet engine handles (most Wi-Fi, IPv6 and UDP flows) skips SQM, so SQM doesn't shape it. Turn offload off for SQM to shape everything.
- Turning "Stop devices skipping Pi-hole" on or off drops name lookups for about 15 seconds while Pi-hole restarts.
- **Speed test:** it runs on the box itself, so on a gigabit line the box's CPU may be the limit rather than the line.
- **Unifi fixes** were confirmed by a tester on a TM line; our test unit has no TM line.

## Included proprietary firmware
This image carries the stock firmware's NPU files (`en7523_npu_rv32.bin`, `en7523_npu_data.bin`), unmodified, for Wi-Fi upload offload. They are only inside the image: they are not in this repository or offered as separate downloads. A build from source without them works, with Wi-Fi upload offload off.

It also carries the TEL port's FXS driver (`airoha_voip`, built with the Silicon Labs ProSLIC API) and its ProSLIC firmware. These are closed source and are only inside the image: they are not in this repository, a package feed or a separate download. A build from source without them works, without the phone port.
