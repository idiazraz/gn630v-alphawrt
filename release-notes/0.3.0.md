## Downloads
- `*-tclinux-factory.bin`: first install, from the stock firmware web UI. Keep `tclinux` in the file name.
- `*-sysupgrade.bin`: upgrade a running AlphaWRT. Never sysupgrade the stock firmware.
- `SHA256SUMS` and `*.sha256`: check the file before flashing.
- `ONT-ISP-TESTER-GUIDE.md`: how to test on your line and report safely (no serials, passwords or MACs).
- `STOCK-VS-ALPHAWRT.md`: how to compare this build with the stock firmware on your line, with the same tests on both.

The stock firmware stays in the other flash bank, so you can always switch back. Read the [recovery guide](https://github.com/idiazraz/gn630v-alphawrt/blob/v0.3.0/docs/RECOVERY.md) before flashing.

## What's new since 0.2.4-test

### Hardware bridging in bridge mode
The box now forwards bridged traffic in its packet engine (PPE) the way the stock firmware does, instead of on the CPU. On our line that takes bridge mode from about 570 down / 370 up with the CPU nearly maxed to 720–760 down / 440 up with the CPU 93% idle.
- Traffic between the fibre and a LAN port is forwarded by the PPE in both directions, from boot, with no setup.
- The hardware entries use the same layout as the stock firmware's own, which we read from a stock unit bridging the same line.
- `bridger` (OpenWrt's bridge offload daemon) finds the bridged flows and hands them to the hardware.
- **bridger fixes:**
  - A refused hardware add is now reported, so the flow falls back to a port that can offload it (`pon0` or `eth0`).
  - Flows that aren't offloaded yet are retried every 10 s.
  - bridger no longer reads a stale netlink reply after polling a flow's counters. That bug made later adds look successful when they weren't, so the hardware never got them and the box bridged on the CPU until bridger was restarted.
- **Bridged IPv6 entries** get the right source MAC, and the PPE debug view shows it correctly.
- **More free memory for network buffers** under load (`vm.min_free_kbytes` 30000, the stock firmware's value).

## Known issues and test limits
- **IPv6 and UDP routing use the CPU:** in combo and router mode, hardware offload covers IPv4 TCP only.
- **Hardware bridging covers the fibre-to-LAN-port path:** bridged traffic to Wi-Fi still goes through the CPU.
- **One line tested:** only TIME has been tested live. The Unifi preset and the Unifi IPTV option haven't been tested on a TM line yet.
- **Moving the line from another router:** TIME allows one PPPoE session per account. Until the old session expires (a few minutes), the login is refused; the box keeps retrying.
- **WireGuard QR code in bridge mode:** LuCI's "Generate configuration" shows no QR code when the box has no Internet address of its own (upstream LuCI). It works in combo or router mode.
- **Untested here:** holding the reset button for a factory reset.
